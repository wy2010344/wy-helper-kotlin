# 02 节点与布局

## 节点树

一切皆 `Node`。容器节点通过 `argChildren()` 声明子节点，子节点用**匿名类**创建：

```kotlin
object : RectNode(this), FlexParam {
    override val layout: LayoutDirection = FlexObject(this)

    override fun StateHolderWithNode<Node, List<Node>>.argChildren() {
        object : WrappedTextNode(this) { /* 子节点 1 */ }
        object : ImageNode(this) {
            override val image: PlatformImage get() = img
        }
    }
}
```

### 匿名类覆盖模式

配置节点不靠构造参数，靠 `override` 属性/方法：

```kotlin
object : WrappedTextNode(this) {
    override val text: String get() = titleSignal.value   // 读信号，值变自动重绘
    override val fontSize: Float get() = 18f
    override val color: ColorInt get() = rgba(80, 80, 80)
}
```

### 惰性建树：`argChildren()` 在首次访问 `children` 时执行

`children` 采用**惰性构建**：节点构造时只声明构建动作，首次真正读取 `children`（布局/绘制/命中测试）才执行 `argChildren()`。因此 `argChildren()` 里可以安全读取**本节点自己声明的属性**：

```kotlin
object : RectNode(this), FlexParam {
    val scrollY = Scroll(this).also { registerScroll(it) }   // 本节点属性

    override fun StateHolderWithNode<Node, List<Node>>.argChildren() {
        object : ScrollContent(this) {
            override val y: Float get() = -scrollY.value     // 构造期读取会拿到默认值，惰性建树后没问题
        }
    }
}
```

若在构造期就执行 `argChildren()`（如属性初始化器里 `context.renderNode { argChildren() }`），匿名类自身的属性尚未初始化，读到的是默认值——这是 Kotlin「基类构造期调用 open 方法」的经典陷阱，惰性建树从机制上规避了它。

## 信号

```kotlin
var count by createSignal(0)          // 赋值 → 依赖该信号的节点自动重算/重绘
val doubled by memo { count * 2 }     // memo 里读信号，自动追踪依赖
```

- 赋值：`count = count + 1`
- 读取：直接 `count`；派生值用 `memo { }` 缓存，比手动维护可靠
- 信号在 `get()` 里读取也生效（上面的 `titleSignal.value` 就是）

## Flex 布局

容器实现 `FlexParam`，并用 `FlexObject(this)` 接入布局引擎：

```kotlin
object : RectNode(this), FlexParam {
    override val direction: Direction = Direction.x           // 主轴：x 水平 / y 垂直（默认 y）
    override val directionJustify: DirectionJustify = DirectionJustify.grow
    override val alignItem: AlignItem = AlignItem.center
    override val alignFix: Boolean = true
    override val gap: Float = 10f
    override val reverse: Boolean = false
    override val layout: LayoutDirection = FlexObject(this)
    ...
}
```

| 属性 | 含义 |
|---|---|
| `direction` | 主轴方向：`Direction.x`（水平）、`Direction.y`（垂直，默认） |
| `directionJustify` | 主轴分配：`start / center / end / between / around / evenly / grow`（默认 `grow`，即由子节点撑出容器尺寸） |
| `alignItem` | 交叉轴对齐：`center / start / end / stretch` |
| `alignFix` | `true` 时交叉轴尺寸由容器内宽/内高决定并拉伸子节点（需容器自己有尺寸）；`false` 时交叉轴取子节点最大尺寸 |
| `gap` | 子节点间距 |
| `reverse` | 主轴反向排列 |

子节点实现 `GrowChild`，把主轴剩余空间分配给自己：

```kotlin
object : ScrollContent(this), GrowChild {
    override fun argGrow(direction: Direction): Float = 1f   // 吃掉剩余空间
    ...
}
```

## 尺寸（重点）

`LayoutSize(value, fromInside)`：

- `fromInside = true`：`value` 是**内容尺寸**，外包尺寸 = value + 两侧 padding
- `fromInside = false`：`value` 就是**外包尺寸**（固定尺寸）

```kotlin
override val argWidth: LayoutSize get() = LayoutSize(420f, true)   // 内宽 420
override val argHeight: LayoutSize get() = LayoutSize(80f, false)  // 外高 80
```

尺寸相关取值：

- `outerWidth / outerHeight`：外包尺寸（含 padding）
- `innerWidth / innerHeight`：内容区尺寸
- `paddingInlineStart/End`、`paddingBlockStart/End`：四个方向 padding，用 `argPadding(direction, startEnd)` 重写

> ⚠️ **尺寸计算注意**：子节点尺寸若依赖父节点布局（`sizeFromParent`），而父节点布局又正依赖子节点尺寸，会触发"重复进入 memo"异常。
> **推荐显式给出尺寸**：
> - 文本：`autoWidth = true`（内容自适应）或显式 `argWidth`
> - 列表行、按钮等：固定 `LayoutSize(w, false)`
> - 需要填满剩余空间的内容：固定一个方向的尺寸 + 另一方向用 `argGrow`

## 绝对定位

节点可以不进 Flex，用 `argPosition` 直接摆坐标（类似 CSS `position: absolute`）：

```kotlin
object : RectNode(this) {
    override fun argPosition(direction: Direction): Float = when (direction) {
        Direction.x -> 100f
        Direction.y -> 40f
    }
    override val argWidth: LayoutSize get() = LayoutSize(200f, false)
    override val argHeight: LayoutSize get() = LayoutSize(30f, false)
}
```

`ScrollContent` 由子类显式 `override val y/x get() = -scroll.value` 做滚动偏移（见 [05](05-列表与滚动.md)）。

## 常用节点

| 节点 | 说明 |
|---|---|
| `Node` | 最基类，不参与布局（无尺寸概念） |
| `LayoutNode` | 有尺寸/布局，不画内容 |
| `RectNode` | 最常用容器，可覆写 `draw` 画背景，参与命中 |
| `ScrollContent` | 滚动容器的内容区（见 [05](05-列表与滚动.md)） |

## 渲染与命中

- 节点覆写 `draw(canvas)` 自绘；`draw` 里务必调用 `super.draw(canvas)` 让子节点继续绘制
- 命中测试默认按节点外包尺寸判定（`RectNode.acceptHit`）；裁剪过的容器覆写 `acceptClip` 限制子树遍历（见 [06](06-事件与焦点.md)）
